# 手绘产品原型 · 领域知识

> 配套 stencil：`phone` `browser`。原型 = 设备框 + 内部 UI 语汇 + 状态语义。用 norm 坐标画，框内构图最稳。

## 第一步：选设备框

- 移动端：`stencil kind:"phone"`，只给 `w`（h 自动 9:19）。内部 UI 往机身里铺。
- 桌面端 / Web：`stencil kind:"browser"`。
- 同一图画多个设备并排对比：每个 phone/browser 给不同的 norm x。

### 有真实设备参照时：用真实尺寸和比例

有明确设备（如 iPhone）别手拍比例——按真实逻辑度量换算：

**iPhone 15 逻辑尺寸 393×852 pt**（比例 h/w = 2.168）。定画布上手机宽 `W`（px），则 `1pt = W/393`，所有度量乘这个系数：

| 元素 | 真实 pt | 说明 |
| --- | --- | --- |
| 状态栏 | 54 | 顶部 |
| 导航栏 | 44 | 标题/操作 |
| 列表行高 | 64 | 聊天行等 |
| 头像 | 40 × 40 | 左间距 16 |
| 标签栏 | 49 | 底部 |
| Home indicator | 底部 ~34 区 | stencil 自动画在 y+h×0.962 |

- **强制真实比例**：phone stencil 默认比例 2.05，要真实就显式传 `h = 2.168 × w`（如 w=260 → h=564）。
- **标签栏要在 home indicator 之上**：stencil 的 home indicator 在 y+h×0.962，标签栏图标/文字别画到那个 y，否则被切。
- 其他参照：iPhone SE/旧机 16:9（h/w=1.78）；iPad 横屏 1024×768。

### 桌面浏览器（macOS Chrome）

**Chrome for macOS 默认窗口 ≈ 1440×900 pt（16:10）**。定画布宽 `W`，则 `1pt = W/1440`，顶栏约 120pt：

| 区域 | 真实 pt | 说明 |
| --- | --- | --- |
| 窗口比例 | 16:10 | h/w=0.625 |
| 红绿灯圆 | 左上 3 个 | 红/橙/绿，半径 ~6 |
| 标签栏 | 48 | 圆角小标签 + 标签文字 |
| 工具栏 | 72 | 后退箭头 + 刷新弧 + 地址栏胶囊 |
| 地址栏 | 圆角胶囊 | r=h/2，左对齐 |
| 内容区 | 顶栏下到窗口底 | 网页内容 |

- **别用 browser stencil**（它画的是通用窗）：macOS Chrome 要手画——红绿灯、标签栏、工具栏三层分开。
- 红绿灯 = 3 个 `ellipse`（红/橙/绿），圆心在标签栏中心线；别在 clear 重画时漏掉。
- 工具栏图标见下节（一律 `icon` 形状）。
- 地址栏文字左对齐（不是居中），与锁同一中心线。

### Chrome 工具栏完整元素集（从左到右，全部在同一中心线 y 对齐）

真实 macOS Chrome 工具栏（不是只有后退/刷新），**图标一律用 `icon` 形状**（见 icons.md），别手画：

| 元素 | 画法 | 说明 |
| --- | --- | --- |
| 后退 ◀ | `icon "chevron-left"` | 黑色可点 |
| 前进 ▶ | `icon "chevron-right"` + `color:"grape"` | 置灰禁用态 |
| 刷新 ↻ | `icon "rotate-cw"` | 环形开口+箭头 |
| 主页 ⌂ | `icon "home"` | 房子 |
| 地址栏 | 圆角 `rrect` 胶囊(r=h/2)，占中部宽度 | 🔒锁在左 |
| 锁 🔒 | `icon "lock"` size≈16 | y=90（胶囊中心 98.5） |
| 书签 ☆ | `icon "star"` | |
| 用户头像 | 彩色 `ellipse` 圆 | 右侧 |
| 菜单 ⋮ | `icon "ellipsis-vertical"` | 最右 |

- **中心线公式**：工具栏 78~118 → 中心 98 → size=24 图标 `y=86`、size=16 图标 `y=90`。先算中心线再反推 y（见 icons.md 定位公式）。
- **置灰用** `color:"grape"`，别用黑色。
- 地址栏文字 `google.com` 与锁同一中心线：size=11 → `y=93`。
- 内容区**水平居中到窗口中轴**（窗 x=70 w=900 → 中轴 x=520）：logo/搜索框/按钮都按 520 对称。

## UI 元素配方（相对一个组件盒子 {x,y,w,h}）

| 元素 | 画法 |
| --- | --- |
| 主按钮 | `rrect` 整盒（r≈h/2 胶囊）+ `hatch` 轻排线表强调色，框内居中 `text` 白/深色字 |
| 幽灵按钮 | `rrect` 整盒但**不填**，只描边；文字用 `ink-you` 蓝 |
| 输入框 | `rrect` 整盒描边 + 内缩进一条 `dash` 占位线（表 placeholder） |
| 搜索框 | 输入框 + 左侧放大镜（小 `ellipse` + 一根斜 `line`） |
| 列表行 | 一行 `line` 分隔上下行；左侧头像/图标、中间标题文字、右侧箭头 `arrow`(小头) |

> **列表行宽度预算**：标题在左、时间/角标在右时，先算标题宽（CJK≈字号宽）别撞右侧元素。标题 size 13、右边距留 ~10px 给时间；长名（如"文件传输助手"6字）会占满半行，宁可缩字号 13 也别让名字压到时间。分隔线缩进对齐（从头像右侧开始，不顶到左边缘）。
| 卡片 | `rrect` 大盒；内部顶部图区留白 + 标题文字 + 一行说明小字 |
| 导航栏（顶） | 机身顶部一条带：左 `text` 返回箭头、中 `text` 标题、右 `text` 操作 |
| 标签栏（底） | 底部一排 4~5 个小图标 + 下方 `text` 字；选中项用 `ink-you` 蓝 |
| 复选框 | 小 `rect` + 里面 `line` 打钩（/ \ 两笔） |
| 开关 toggle | 胶囊 `rrect`(r=h/2) + 一颗圆 `ellipse` 当滑块；开=滑块靠右且用 `green`，关=靠左灰 |
| 头像 | 小圆 `ellipse`；或圆里两点一头肩 `spline` 表人像 |
| 标签 chip | 小胶囊 `rrect` + 短文字 |
| 进度条 | 长 `rrect` 凹槽 + 内填一段（`hatch` 或加粗 felt 实线表已走部分） |
| 底部弹窗 sheet | 机身下半张大 `rrect`，顶部一条把手横线 |
| 未读角标 | 小圆 `ellipse` 在图标右上角，内写数字 |

## 状态与配色语义

- `ink` 墨黑 = 主文字 / 边框
- `ink-you` 蓝 = 可点交互（链接、选中、主色按钮）
- `green` 绿 = 成功 / 开启 / 完成 / **当前选中态**（微信 tab 高亮）
- `red` 红 = 警示 / 删除 / 错误 / 未读角标
- `tangerine` 橙 / `teal` 青 = 分类强调、图表分区、头像区分
- `hatch` 排线 = 选中态 / 按下态 / 强调底色
- `dash` 虚线 = 禁用 / 不可点 / 占位 / 折叠边界

## 分层与对齐规范（让用户一眼认同）

**用线宽分层，别让所有线一样粗**：
- **设备框粗**（`size:1.8`）= 硬件边界，视觉上最外层
- **内部分隔线细**（`size:0.5`）= 内容结构，退到框线之下
- 标题/主操作可用颜色强调（如微信绿 `green`），状态用颜色（选中=绿、未读=红、打字中=绿）

**列表行三列网格对齐**：
- **头像列**左对齐（如 x=413），**文字列**左对齐（如 x=451，固定缩进），**时间列**右对齐（如 x=602）
- **垂直居中**：头像中心 = 文字块中心 = 行中心。行中心 y = 行顶 + 行高/2；头像 y = 行中心 − 头像高/2；文字块（标题+预览）整体垂直居中在行内
- 行分隔线从文字列开始缩进（不顶到左边缘），头像下方不画线

**区域分隔**：导航栏底、标签栏顶用通栏细线（从设备内左到右），与列表行分隔线（缩进）区分

## 间距规范（一张图只用一套档位）

> 用户反馈："避免整体太紧凑，留白和间距要有统一规范，一个场景别出现很多不一样的规格。"开画前先定档位，全图共用；自查时对照。

**统一档位（px）**：

| 关系 | 档位 | 例（窗口 x70 w900，内容区 90~950） |
| --- | --- | --- |
| 页面外边距（窗口→内容） | **20** | 内容区 x 90~950 |
| 大栏之间（首屏三栏等） | **16** | 菜单 90~230 / 轮播 246~634 / 面板 650~950 |
| 横排卡片之间 | **20** | 4 卡 w200：x=90/310/530/750 |
| 卡内边距 | **10~12** | 卡内文字 @卡x+10 |
| 分隔线→内容（楼层标题） | **≥14** | 线 y=380 → 标题 y=394 |
| 同栏行距（列表/菜单行） | **17~18 pitch** | 菜单 8 行 y=243+17k |

**定档方法**：先算可用空间再分——如 4 卡 w200 + 3 gap = 860 可用 → gap=(860−800)/3=20，全图横排卡一律用这个值；别这排 12 那排 16。

**紧凑自查**：任两个相邻元素间距 < 10px、或文字贴框线 < 4px → 重排。留白均匀比"塞得多"重要。

## 标注

- 引线注释：`arrow`（或无箭头 `line`）从元素指到旁边，末端 `text` 写说明。
- 流程演示：在多个手机框之间画 `arrow`，线上标注点击动作（"点登录"→）。

## 常见错法

- 不画设备框直接画 UI → 看不出是手机还是桌面。**先 phone/browser，再铺 UI。**
- 文字 size 用 norm 思维传 0.03 → text 的 size 恒为 px（~20~30），别当比例传。
- 一堆框没有间距 → 组件间留 ≥0.04 norm 高。
- 状态全是墨黑 → 选中/禁用要靠 hatch/dash/颜色区分，否则原型没有"态"。
